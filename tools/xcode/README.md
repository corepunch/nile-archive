# Xcode projects

Each game has a committed native project beside its sources,
`games/<game>/<game>.xcodeproj`, with a macOS and an iPad target, generated by
`tools/xcode/generate.py` the way orion-ui generates its app projects:

```sh
python3 tools/xcode/generate.py nile-archive --unsigned
python3 tools/xcode/generate.py relic-rush --unsigned
open games/relic-rush/relic-rush.xcodeproj
```

Choose the `<game>-macos` or `<game>-ipad` scheme. The iPad scheme runs in
the Simulator and on iPads (iPadOS 16+); the Mac target needs macOS 12+. For
device builds select a team in **Signing & Capabilities** and keep automatic
signing; no team or certificate is needed for macOS or Simulator builds. With
`--unsigned`, regeneration preserves signing settings, bundle identifiers and
shared schemes already in the project (`--settings-from` reads them from
another project; `--team` sets a team).

What the projects contain:

- The engine's sources (`engine/*.c`, `lua_lib.c`, `launcher.c`) compiled
  directly, with `GAME_IN_BUNDLE=1`: the launcher finds `lua/` and `data/`
  through `SDL_GetBasePath()`, i.e. inside the app bundle, where the two
  folders are copied as folder references. No build products are written into
  the game folder; nothing is generated at build time.
- **SDL2 from the `engine/third_party/SDL` submodule**: SDL's own
  `Xcode/SDL/SDL.xcodeproj` is a project reference, its `Framework` (macOS)
  or `Framework-iOS` target a dependency, and `SDL2.framework` is linked and
  embedded. The generator reads SDL's target identifiers from that project,
  so updating the submodule needs no change here. Clone with `--recursive`
  or run `git submodule update --init` first.
- `Generated/macos-Info.plist`, `Generated/ipad-Info.plist` (orientations per
  game: landscape for Nile Archive, portrait for Relic Rush; full screen,
  status bar hidden) and `Generated/macos.entitlements` (App Sandbox; saves
  go through `SDL_GetPrefPath`, so no file access is needed). Both plists
  declare `ITSAppUsesNonExemptEncryption` false.
- Shared schemes in `xcshareddata/xcschemes`, so Xcode Cloud can pick a
  committed project and scheme directly; it checks out public submodules on
  its own.

Identifiers and files are deterministic, so regenerating an unchanged project
changes nothing; `make test` runs `generate.py --check`, which regenerates both
projects into a temporary folder and fails if a committed file differs.
Regenerate after adding an engine module to the Makefile's `ENGINE` list or
changing build settings; editing Lua or data needs nothing.

Build from the command line:

```sh
xcodebuild -project games/relic-rush/relic-rush.xcodeproj -scheme relic-rush-macos \
  -derivedDataPath build/xcode/DerivedData build
xcodebuild -project games/relic-rush/relic-rush.xcodeproj -scheme relic-rush-ipad \
  -destination 'generic/platform=iOS Simulator' -derivedDataPath build/xcode/DerivedData-ipad \
  CODE_SIGNING_ALLOWED=NO build
```

The CI `xcode` job builds both games' iPad targets for the Simulator this way.
